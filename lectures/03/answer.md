# 第3回 解答

## 演習

- 第1回（素のLLM）とエージェントの回答の違い：
  - 質問は「AIE2026の講座の宿題にある『3レベル』とは何ですか？」
  - 第1回の `app.ask` は講座固有の知識を持たないため、「一般的には Level 1 基礎 / Level 2 応用 / Level 3 発展」といった一般論で回答した。「応用」という名称は講座の実際の区分（実装）とは異なり、「どれか1つに取り組めば完了」という点にも触れなかった。
  - 第3回の `app.agent` は用語集を検索したうえで、「基礎・実装・発展の3段階で、どれか1つに取り組めば完了。原則として採点はしない」と用語集の内容どおりに回答し、最後に関連する回として第1回も示した。
- `--trace` で見えたツール呼び出し（ツール名と引数）：
  - 「3レベル」の質問：`search_glossary({'query': '3レベル'})` の1回
  - 「LoRAとQLoRAの違いは？」：`search_glossary({'query': 'LoRA'})` と `search_glossary({'query': 'QLoRA'})` の2回。docstring の「query には調べたい用語を1つだけ入れる」という指示どおり、用語を1つずつ検索した。
  - 「第2回の内容から確認問題を1問出して」：`make_quiz({'lecture': 2})` の1回
- 1つの質問での LLM 呼び出し回数（`requests`）：
  - 3つの質問とも `requests=2` だった（第1回の `app.ask` は1回）。1回目でツールの呼び出しを判断し、2回目でツールの実行結果をもとに回答を生成している。
  - 「LoRAとQLoRAの違いは？」ではツールを2回呼び出しているが、1回目の応答で2件の検索をまとめて要求していたため、`requests` は2のままだった。
  - 入力トークン数は「3レベル」が 935、LoRA/QLoRA が 1348 だった。ツールの説明文や検索結果が入力に加わるため、第1回（21トークン）より大幅に増えている。
- 追加したツールと、docstring に書いた説明：
  - `make_quiz(lecture: int)`：指定された回の用語を用語集から1つ選び、「『○○』の意味は？」という問題文と、正解となる定義を JSON で返す。該当する用語がない回を指定された場合は、用語が存在する回の一覧を返す。
  - docstring：「指定した回の用語から 1つを選び、確認問題と答えを返す。「第2回の確認問題を出して」のように、復習用の問題を求められたときに使う。」
  - 結果：「Hugging Face Hub」に関する問題が出題された。ツール自体は正解も返しているが、エージェントは答えを伏せ、「答えを確認したいときは聞いて」と添えて出題した。`INSTRUCTIONS` の「宿題の答えそのものは書かず、ヒントで導く」という指示が影響したと考えられる。

## 宿題

- 取り組んだレベル：基礎
- やったこと：
  - 「用語集を検索してから答える」という指示を外したときに、エージェントが検索せずに回答するようになるかを検証した。
  - 実験1：`INSTRUCTIONS` から「用語や講座に固有のことを答える前に、必ず search_glossary で用語集を確認する。」の1行だけを削除した。
  - 実験2：実験1の結果を踏まえ、`INSTRUCTIONS` の該当行を消したまま、`search_glossary` の docstring からも「AIエンジニアリングの用語や、この講座（AIE2026）に固有の言葉について答える前に使うこと。」の一文を削除した。
  - いずれの実験でも、「AIE2026の講座の宿題にある『3レベル』とは何ですか？」と「LoRAとQLoRAの違いは？」の2問を `--trace` 付きで2回ずつ実行し、演習時の結果と比較した（実験後は元のコードに戻した）。
- 結果：

  | | 元の設定 | 実験1：INSTRUCTIONS の行を削除 | 実験2：docstring の文も削除 |
  |---|---|---|---|
  | 3レベル：ツール呼び出し | `search_glossary('3レベル')` | 2回とも同じ | 2回とも同じ |
  | 3レベル：入力トークン | 935 | 887 | 827 |
  | LoRA/QLoRA：ツール呼び出し | `LoRA` と `QLoRA` を1回ずつ | 2回とも同じ | 2回とも同じ |
  | LoRA/QLoRA：入力トークン | 1348 | 1300 | 1240 |
  | requests | 2 | 2 | 2 |

  - いずれの設定でも用語集の検索が行われ、呼び出されたツール名・引数・`requests` に変化はなかった。
  - 入力トークン数は削除した文の分だけ毎回減少し、実験1で 48 トークン、実験2でさらに 60 トークン減った。
  - 回答内容はどの設定でも用語集に沿ったものだった。ただし LoRA/QLoRA の質問では、「Quantized LoRA」や「FP16 など」のように用語集にない表現を補足する回と、用語集の定義をほぼそのまま返す回があり、これは指示の有無にかかわらず実行ごとにばらつきが見られた。
- 気づき・疑問：
  - 実験1でも検索が行われたため、docstring 側の「答える前に使うこと」という指示が効いているのではないかと予想したが、実験2で両方を削除しても検索は行われ、予想は外れた。
  - 残っている手がかりとしては、ツール名（`search_glossary`）や説明文の「講座の用語集から用語を検索し」という記述、`INSTRUCTIONS` の「AIE2026の学習支援エージェント」という役割設定と「用語集に見つからないことは推測で断定せず」という指示、そして質問文に含まれる「AIE2026」という語が挙げられる。用語集を検索するツールが与えられているだけで、モデルは「講座や用語に関する質問ならこれを使うべきだ」と自律的に判断しているように見える。
  - 一方で、プロンプトや docstring の文面は LLM を呼び出すたびに入力として送られるため、トークン数には確実に影響する。今回のように挙動に差が出ない重複した指示であれば、削ったほうがコストを抑えられる。
  - 疑問と追加の実験：「LoRA」のように広く知られた用語でも検索したのは、講座に関する質問だと判断したからなのか、また講座に触れない質問なら検索せずに答えるのかを確かめるため、元の設定のまま以下の2問を2回ずつ実行した。
    - 「Transformerとは？」：質問文で講座には触れていないが、2回とも `search_glossary('Transformer')` を呼び出した。用語集にない語のため「見つかりませんでした」が返り、1回目は「用語集にはない」と断ったうえで一般知識として補足したが、2回目は「お答えできません」とだけ回答し、実行によって対応が分かれた。また、1回目は関連する回として「第1回」を挙げたが、用語集に載っていない語であるため根拠のない出力となっている。
    - 「日本の首都はどこですか？」：2回ともツールを呼ばず、`requests=1` で「東京です」と回答した。入力トークン数は 391 で、ツールを使った質問の半分以下だった。ただし、2回とも回答の末尾に「（第1回）」と付記された。
  - この追加実験から、モデルは質問文に講座名が含まれるかではなく、「AI関連の用語かどうか」で検索の要否を判断しているように見える。これは元の docstring にある「AIエンジニアリングの用語や」という記述とも合致する。ただ、実験2でこの一文を消しても「LoRA」を検索したことから、明示的な指示文だけでなく「AI講座の学習支援エージェントに用語集検索ツールが用意されている」という状況自体から判断していると考えられる。また、「回答の最後に、関係する回を示す」という指示が「日本の首都」のような無関係な質問にも機械的に適用されたことから、指示は適用する場面を限定して書かないと、意図しない場面でも過剰に守られてしまうことが分かった。
